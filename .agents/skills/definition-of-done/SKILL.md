# Definition of Done

Правила: `rules.md` §11. Задача не считается выполненной, пока не пройдены проверки,
применимые к её изменениям.

## 1. Обязательный минимум

```bash
php -l <каждый изменённый PHP-файл>
php artisan route:list              # если менялись роуты/контроллеры
./vendor/bin/pint --test            # стиль PHP
./vendor/bin/phpstan analyse        # статический анализ
npm run lint                        # ESLint + Prettier
npx vue-tsc --noEmit                # типы во Vue/TS
```

Команды выполняются фактически, а не «предполагаются». Если команда не может быть выполнена
(нет зависимостей, не настроен Playwright), это явно сообщается пользователю.

## 2. По характеру изменений

| Изменено | Дополнительно |
|---|---|
| Миграции / модели | `php artisan migrate` на локальной БД, проверка сидеров |
| Сидеры | повторный запуск `db:seed` — данные не дублируются |
| `config/handbooks.php` | `php artisan route:list \| grep -E "handbook\|enum"` |
| OA-аннотации | только если Swagger подключён: `php artisan l5-swagger:generate` |
| Новый enum | перевод в `lang/ru/enums.php`, `enum` в OA-схеме |
| Blade-шаблоны | открыть страницу без JS — контент читается, ссылки работают |
| Vue-острова | `npm run build`, проверка монтирования и `data-props` |
| Стили / токены | сверка с `docs/handoff/04-tokens`, проверка 390 px и 1440 px |
| Passport / middleware | `php artisan route:list`, ручной сценарий без токена |
| Playwright | `npx playwright test` на поднятом `composer dev` |

## 3. Проверка слоёв (глазами)

- Контроллер: только DTO → сервис → `view()` или презентер; нет БД, вычислений, валидации.
- Request: все правила здесь, `$dtoClassName` задан.
- Сервис: статические методы, транзакции, доменные исключения, проверки доступа в начале.
- Репозиторий: все мутации через него, сложные выборки здесь, raw SQL только здесь.
- Resource: `getFields`/`getRelation`/`getEnum`, FK не выводится как `*_id`, нет догрузок.
- Модель: `$fillable`/`$casts` соответствуют новым полям, связи `r*` на месте.
- Blade: разметка и данные, никаких запросов к БД и бизнес-логики.

## 4. Контракты

- Роуты страниц в `routes/web.php`, JSON — в `routes/api.php`; справочники — из пакета.
- Swagger: `responses`, `tags`, параметры GET; `path` без префикса API; схемы перегенерированы.
- Enum: у каждого case есть перевод; фронт получает `{id, name}`.
- Справочники: только конфиг, без ручных роутов; Request подключает DTO.
- Vue-острова: имя в реестре `app.ts`, контейнер с `data-island`, SEO-контент вне контейнера.
- Токены CSS и шрифты — из `docs/handoff/`, без «своих» значений на глаз.

## 5. Гигиена изменений

- Не тронут `vendor/`; правки пакетов `vasichmen/*` — в их репозиториях.
- Нет отладочного кода (`dd`, `dump`, `var_dump`, `console.log`, закомментированных блоков).
- Нет случайных реформатирований чужих файлов.
- Публичные поля/методы/ключи JSON не переименованы без согласования.
- Коммиты и пуш не создавались без явной просьбы пользователя.

## 6. Отчёт пользователю

Указать:

1. Что сделано (файлы и суть изменений).
2. Какие команды проверки выполнены и их результат.
3. Что осталось непроверенным и почему (например, нет доступа к БД, Playwright не настроен).
4. Риски и follow-up (правки пакетов `vasichmen/*`, миграции данных, доработка дизайна).

## 7. Красные флаги — задача не готова

- Любая из команд §1 не запускалась (и это не оговорено).
- Есть валидация вне Request или бизнес-логика в контроллере/Blade.
- Есть мутация модели в обход репозитория.
- Новый enum без перевода.
- Ответ API без Resource/презентера.
- В задаче появился ручной роут справочника.
- SEO-контент отдаётся только через JS-остров.
- Добавлен `vue-router`, Inertia, SSR или Composition API.
