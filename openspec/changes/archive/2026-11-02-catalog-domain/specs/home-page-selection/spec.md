# Spec Delta

## Purpose

Определяет, какой сезон и какие товары получает главная страница по адресу и локальному месяцу пользователя, чтобы выдача была предсказуемой и проверяемой.

## ADDED Requirements

### Requirement: Сезон по умолчанию определяется локальным месяцем пользователя
Система SHALL выбирать стартовый сезон по месяцу, который передаёт фронтенд: декабрь–февраль — зима, март–май — весна, июнь–август — лето, сентябрь–ноябрь — осень. Сервер MUST NOT применять собственный часовой пояс.

#### Scenario: Зимние месяцы
- **WHEN** фронтенд передаёт месяц декабрь, январь или февраль
- **THEN** стартовым сезоном является зима

#### Scenario: Весенние месяцы
- **WHEN** фронтенд передаёт месяц март, апрель или май
- **THEN** стартовым сезоном является весна

#### Scenario: Летние месяцы
- **WHEN** фронтенд передаёт месяц июнь, июль или август
- **THEN** стартовым сезоном является лето

#### Scenario: Осенние месяцы
- **WHEN** фронтенд передаёт месяц сентябрь, октябрь или ноябрь
- **THEN** стартовым сезоном является осень

#### Scenario: Месяц не передан
- **WHEN** фронтенд не передал месяц и сезон не задан в адресе
- **THEN** выбирается первый сезон по порядку сортировки

### Requirement: Сезон можно выбрать адресом
Система SHALL открывать сезон, указанный в адресе параметром `season`, вместо сезона по умолчанию, если значение соответствует slug существующего сезона.

#### Scenario: Выбор сезона в адресе
- **WHEN** клиент запрашивает главную с `?season=winter`
- **THEN** страница открывается с зимним сезоном независимо от текущего месяца

#### Scenario: Сезон из адреса определяет содержимое
- **WHEN** клиент запрашивает главную с `?season=spring`
- **THEN** заголовок, лид и товары страницы относятся к весеннему сезону

### Requirement: Товары вне наличия не попадают в списки
Система SHALL исключать товары со статусом «нет в наличии» из сетки десктопа, плиток телефона, колеса и счётчиков товаров; такие товары MUST NOT увеличивать число продуктов сезона.

#### Scenario: Товар вне наличия скрыт из сезона
- **WHEN** в сезоне есть товар со статусом «нет в наличии»
- **THEN** его нет в сетке, плитках и на колесе
- **AND** число продуктов сезона его не учитывает

#### Scenario: Счётчики сезонов без товара вне наличия
- **WHEN** проверяется число продуктов сезонов
- **THEN** у зимы 9 продуктов, у весны 8, у лета 9, у осени 9

### Requirement: Товар доступен по прямой ссылке
Система SHALL отдавать данные товара, указанного в адресе параметром `product`, независимо от его статуса наличия.

#### Scenario: Прямая ссылка на товар вне наличия
- **WHEN** клиент запрашивает главную с параметрами `season` и `product`, где `product` указывает на товар со статусом «нет в наличии»
- **THEN** данные этого товара доступны для открытия карточки
- **AND** товар по-прежнему отсутствует в списках сезона

#### Scenario: Прямая ссылка на обычный товар
- **WHEN** клиент запрашивает главную с параметрами `season` и `product`, где `product` указывает на товар в наличии
- **THEN** данные товара доступны для открытия карточки

### Requirement: Следующий сезон идёт по цепочке
Система SHALL определять следующий сезон по цепочке осень → зима → весна → лето → осень и брать для полосы «Дальше — …» подпись и иконку из данных следующего сезона.

#### Scenario: Цепочка сезонов
- **WHEN** для каждого сезона определяется следующий
- **THEN** после осени идёт зима, после зимы — весна, после весны — лето, после лета — осень

#### Scenario: Данные полосы «Дальше — …»
- **WHEN** отображается полоса «Дальше — …»
- **THEN** её подпись взята из поля следующего сезона
- **AND** её иконка взята из поля иконки следующего сезона, а не из его товаров

### Requirement: Пустой сезон открывается с пустым состоянием
Система SHALL открывать сезон без видимых товаров с его текстом пустого сезона и ссылкой на сезон, в котором есть товары.

#### Scenario: Сезон без товаров
- **WHEN** выбран сезон, в котором нет видимых товаров
- **THEN** страница открывается с текстом пустого сезона
- **AND** содержит ссылку на сезон с товарами

### Requirement: Диапазон месяцев передаётся без локализации
Система SHALL передавать сохранённый диапазон месяцев сезона (`mobileSub`) как сырое значение; название текущего месяца, регистр и формат подписи определяет фронтенд по часовому поясу пользователя.

#### Scenario: Подпись сезона на телефоне
- **WHEN** фронтенд получает данные сезона
- **THEN** `mobileSub` содержит диапазон месяцев из данных сезона
- **AND** сервер не подставляет название текущего месяца
