# Design

## Context

Каркас создаётся с нуля: в репозитории есть только `docs/`, `openspec/`, `.agents/`, `.opencode/`,
`AGENTS.md`, `rules.md`; `composer.json`, `package.json`, `app/`, `routes/`, `resources/`
отсутствуют. Мотивация — `proposal.md` («Why»), требования — дельты в `specs/*/spec.md`.

Ограничения, которые определяют подход:

- Laravel 13 / PHP 8.5, Vite 8 / Node 26, Vue 3 (только Options API), TypeScript strict,
  PostgreSQL 15.2 (ТЗ §15).
- Blade отдаёт весь индексируемый контент; Vue — только острова. SPA, SSR, Inertia,
  `vue-router` не используются (`AGENTS.md` §2, §5.10; `rules.md` R-FE).
- Один entry-point `resources/js/app.ts`; данные острова приходят из `data-props`, а не
  запросом при монтировании.
- Страницы публичные, авторизации в MVP нет; API и доменной схемы БД в этом change нет.
- Локальный запуск — одна команда; Playwright гоняется на уже поднятом `composer dev`
  (`rules.md` R-QA-2).
- В репозитории нет ни одного коммита; `docs/tz` в git не хранится.

Laravel 13 предоставляет `composer dev` → `php artisan dev` (server, queue, logs, vite)
и `composer setup`. Это отличается от буквы ТЗ §15.4 (там `concurrently`), но сохраняет
требуемый результат и снимает необходимость писать свой процесс-менеджер.

Поток каркаса:

```text
GET / → routes/web.php → PageController → view(layout + page)
                                      └─ @vite → manifest (prod) / hot (dev) → CSS + app.ts
HTML [data-island] → app.ts → registry → createApp → Vue-компонент
```

## Goals / Non-Goals

**Goals:**

- Поднять Laravel 13, Vite/Vue/TypeScript и связать их так, чтобы `composer dev` открывал
  рабочую страницу, а `npm run build` давал production-сборку.
- Зафиксировать контракт страниц: именованные web-роуты, тонкий контроллер, Blade-layout,
  метаданные на страницу, детерминированный 404 и публичный доступ.
- Зафиксировать контракт островов: реестр, монтирование по `[data-island]`, props из HTML,
  изоляция ошибок одного острова от остальной страницы.
- Дать проверяемый «проверочный остров», чтобы протестировать рантайм до появления реальных
  интерактивных блоков.
- Настроить команды качества и браузерные проверки, которые можно запускать в ежедневной
  работе без ручной сборки.

**Non-Goals:**

- Реальный дизайн главной, колесо сезонов, каталог, карточки, мок-контент и сезоны.
- Шрифты WOFF2, полная типографика, SVG-пайплайн, иконки и pixel-perfect сверка.
- Полная шапка/меню/футер по ТЗ §4.2 — в каркасе только минимальная навигация, нужная
  для проверки ссылок и прямых адресов.
- Доменные сущности, миграции, сидеры, `vasichmen/*`, Passport, справочники и JSON API.
- Ленивая загрузка островов, модули-сторы, модалки, карусели, FAB.
- Open Graph, Twitter Card, JSON-LD, `robots.txt`, `sitemap.xml`, аналитика.
- CI/CD, production-деплой и выбор production-драйверов session/cache/queue.

## Decisions

### 1. Bootstrap: скелет Laravel 13 во временном каталоге и слияние

**Решение.** Скелет ставится в отдельный временный каталог
(`composer create-project laravel/laravel:^13.0 … --no-install --no-scripts`), затем
переносится в корень репозитория. Существующие `AGENTS.md`, `rules.md`, `docs/`, `openspec/`,
`.agents/`, `.opencode/`, `.git/` не перетираются. `.gitignore` объединяется, приоритет —
у проектного. После слияния `composer install` выполняется уже в проекте.

**Почему.** `create-project` не работает в непустой каталог, а собирать скелет вручную
(`composer require laravel/framework` + копирование `bootstrap/`, `config/`, `storage/`)
легко ошибиться. Временный каталог даёт ровно тот скелет, который поддерживает фреймворк.

**Альтернативы.** `laravel new` — та же проблема с непустым каталогом. Отдельная ветка или
worktree — в репозитории ещё нет HEAD. Ручной скелет — лишний риск пропустить служебные
файлы.

### 2. Frontend: официальный `laravel-vite-plugin`, один entry-point, без starter kit и Tailwind

**Решение.** `vite.config.ts` подключает `laravel-vite-plugin` и `@vitejs/plugin-vue`;
входы — `resources/css/app.css` и `resources/js/app.ts`; alias `@` → `resources/js`.
`app.css` импортирует `tokens.css` (копия `docs/handoff/04-tokens/tokens.css`) и задаёт
базовую типографику. Tailwind и `@tailwindcss/vite` из скелета удаляются.

**Почему.** Один entry-point — прямое требование `R-FE-3`. Starter kits тянут SPA-подходы
(Inertia/React/Vue-router) и Composition API, которые запрещены. Tailwind конфликтует
с дизайн-системой на CSS-переменных: стили должны строиться на токенах, а не на utility-классах.

**Альтернативы.** Starter kit — нарушает R-FE-2/R-0.9. Tailwind — дублирует токены и
усложняет ревью. Отдельный бандл на каждый остров — дублирует общий рантайм и разводит
состояние.

### 3. Страницы: именованные роуты, один `PageController`, Blade-layout и meta-партиал

**Решение.** В `routes/web.php` — пять GET-роутов (`home`, `about`, `preorder`,
`how-to-order`, `contacts`) и `Route::fallback([PageController::class, 'notFound'])`.
`PageController` содержит пять тонких методов и `notFound()`; каждый передаёт в view
`$meta` (`title`, `description`, `canonical`) и ничего не вычисляет. `layouts/app.blade.php`
отдаёт `lang="ru"`, подключает `partials/meta.blade.php` и `@vite`, содержит минимальный
`<header>` с пятью ссылками и `<main>`. Страницы разделов — `h1`, текст-заглушка и ссылка
на `/`.

**Почему.** Контент и метаданные попадают в исходный HTML без JavaScript. Fallback-роут
возвращает нашу 404-страницу с кодом 404 независимо от `APP_DEBUG`; `abort(404)` в debug-
режиме показал бы страницу Ignition вместо страницы сайта.

**Альтернативы.** Route closures — логика в роутах. `Route::view` — некуда передать
метаданные. `abort(404)` — поведение зависит от `APP_DEBUG`. Отдельный контроллер на каждую
страницу — лишние файлы без выгоды.

### 4. Страницы ошибок: отдельный layout без Vite

**Решение.** `errors/404.blade.php` и `errors/database.blade.php` используют
`layouts/error.blade.php` с небольшим inline-блоком CSS и meta-партиалом с безопасными
значениями по умолчанию. `@vite` в этих шаблонах не вызывается.

**Почему.** Страница ошибки должна открываться, даже если production-сборка отсутствует
или сломана. Если бы 404 зависел от manifest, ошибка ассетов превращалась бы в ошибку
страницы ошибки.

**Альтернативы.** Общий `layouts/app.blade.php` — визуально консистентнее, но создаёт
зависимость от сборки. Отдавать стандартную страницу Laravel — не выполняет требование
о HTML-странице сайта и зависит от `APP_DEBUG`.

### 5. Контракт островов: реестр, `createApp` на контейнер, `data-props`

**Решение.** `resources/js/app.ts` содержит реестр `Record<string, Component>` и обходит
`document.querySelectorAll('[data-island]')`. Для каждого контейнера:

1. имя берётся из `dataset.island`; нет в реестре → `console.warn` и пропуск;
2. `dataset.props` разбирается через `JSON.parse` в `try/catch`; ошибка → `console.error`
   и пропуск; допустим только JSON-объект;
3. `createApp(component, props).mount(el)` вызывается в `try/catch`, чтобы падение одного
   острова не останавливало остальные;
4. монтирование затрагивает только контейнер, серверный HTML вокруг не меняется.

В реестр добавляется проверочный остров `scaffold-probe` (Options API): показывает
`message` из props и кнопку, меняющую локальное состояние. Он нужен только для проверки
рантайма и удаляется, когда появится первый реальный остров.

**Почему.** Это минимальный контракт, который покрывает `specs/client-islands/spec.md`:
монтирование по разметке, props из HTML, устойчивость к неизвестному имени и битым данным,
сохранение серверного контента. Отдельный `createApp` на контейнер исключает общий корневой
экземпляр и не требует гидратации.

**Альтернативы.** Глобальный `window.mountIsland` — загрязняет глобальную область и
противоречит R-FE-6. Один корневой экземпляр Vue — запрещён. Zod в рантайме островов —
props приходят из Blade и доверенны; zod появится для данных из внешних API. Ленивая
загрузка через `IntersectionObserver` — не нужна, пока нет островов ниже фолда; контракт
позволяет добавить её позже без изменения разметки.

### 6. Проверка отказов островов в Playwright — подменой HTML, без тестовых роутов

**Решение.** В браузерном тесте `page.route` перехватывает ответ главной и добавляет в HTML
контейнеры с незарегистрированным именем и с битым `data-props`. Реальный `app.ts` обрабатывает
их так же, как в production. Отдельный тестовый роут или скрытые контейнеры на публичной
странице не добавляются.

**Почему.** Проверяется настоящий рантайм, а в приложении не появляется тестовая поверхность,
которую придётся сопровождать и случайно выкатывать.

**Альтернативы.** Скрытые контейнеры на главной — шум в консоли и мусор в production HTML.
Роут `/_islands-fixture` — дополнительный код и маршрут, которого нет в требованиях.
Юнит-тест с jsdom — потребовал бы второго тестового рантайма (Vitest) ради одного сценария.

### 7. Драйверы: file session/cache, sync queue; миграции не запускаем

**Решение.** `.env.example` переводится на PostgreSQL по ТЗ §15.3, но
`SESSION_DRIVER=file`, `CACHE_STORE=file`, `QUEUE_CONNECTION=sync`. Дефолтные миграции
Laravel остаются в скелете, однако `composer setup` их не выполняет: доменных миграций
в этом change нет. `composer setup` делает install/env/key/npm install/build.

**Почему.** Анонимные публичные страницы не должны писать сессии в БД и не должны требовать
схему только для того, чтобы открыться. Proposal фиксирует отсутствие изменений схемы БД.
Sync-очередь позволяет `artisan dev` держать процесс `queue` без таблицы `jobs`.

**Альтернативы.** Database-драйверы + миграции — каждая страница зависит от схемы и лишних
запросов; для каркаса это преждевременно. Cookie-сессии — допустимый вариант, но file-драйвер
ближе к локальной отладке и не меняет поведение middleware.

### 8. Диагностика БД: local-only middleware и 503

**Решение.** `EnsureDatabaseIsAvailable` регистрируется в global middleware через `prepend`.
В окружении `local` он вызывает `DB::connection()->getPdo()`; при исключении пишет его в лог
(`report()`) и возвращает `response()->view('errors.database', [], 503)`. В остальных
окружениях middleware сразу передаёт запрос дальше. Страница ошибки не показывает текст
исключения и параметры подключения, только понятную подсказку.

**Почему.** Требование `specs/local-development/spec.md` проверяется на уровне ответа
страницы. Явная проверка подключения не маскирует SQL-ошибки (в отличие от перехвата всех
`QueryException`) и срабатывает до сессий и будущих DB-зависимых middleware. `DB_HOST=127.0.0.1`
из ТЗ даёт быстрый `connection refused`, а не долгое ожидание.

**Альтернативы.** Database-сессии — проверка была бы «естественной», но каждая страница
зависела бы от БД. Render-callback на `QueryException` — сложно отличить потерю связи от
ошибки SQL и легко спрятать реальную проблему. Проверка только внутри `composer dev` — не
покрывает сценарий «страница запрошена при недоступной БД».

### 9. Локальный запуск: `composer dev` → `php artisan dev`

**Решение.** Оставляем штатный скрипт Laravel 13: `composer dev` вызывает `php artisan dev`,
который поднимает `server`, `queue`, `logs` и `vite`, а при прерывании завершает все процессы
и освобождает порт. Отдельные `php artisan serve` и `npm run dev` остаются рабочими.

**Почему.** Это первое лицо фреймворка: меньше своего кода, корректная остановка процессов
и автоматический перезапуск упавших процессов. Набор процессов совпадает с ТЗ §15.4.

**Альтернативы.** Свой `concurrently`-скрипт — дублирует функциональность фреймворка и
требует отдельной обработки сигналов. Только `serve` + `vite` — не выполняет ТЗ в части
очереди и логов.

### 10. Playwright: без `webServer`, на поднятом `composer dev`

**Решение.** `playwright.config.ts` использует `baseURL` из `PLAYWRIGHT_BASE_URL`
(по умолчанию `http://127.0.0.1:8000`) и `globalSetup`, который проверяет доступность
страницы и подсказывает запустить `composer dev`. Свой `webServer` не настраивается.

**Почему.** `R-QA-2` прямо запрещает отдельный веб-сервер для тестов. Так проверяется тот же
dev-режим, в котором работает разработчик, включая Vite и `public/hot`.

**Альтернативы.** `webServer` с `serve` + `vite` — нарушает R-QA-2 и дублирует процессы.
Тесты на production-сборке — не проверяют dev-режим и требуют отдельного запуска.

### 11. Качество: Pint, Larastan, ESLint/Prettier, `vue-tsc`

**Решение.** В `package.json`: `build`, `dev`, `lint` (ESLint + Prettier check), `format`,
`typecheck` (`vue-tsc --noEmit`), `test:e2e`. В `composer.json`: `dev`, `setup`, `test`,
`analyse` (PHPStan). Pint — preset Laravel; Larastan — level 6 на `app/`. ESLint flat config
с `typescript-eslint` и `eslint-plugin-vue`; Prettier не конфликтует с ESLint.

**Почему.** `definition-of-done` требует эти команды; в каркасе дешевле зафиксировать их
сразу, чем добавлять к первому доменному коду. PHPStan на пустом `app/` почти ничего не
стоит, но задаёт планку.

**Альтернативы.** Без PHPStan/ESLint — технический долг с первого коммита. Только Prettier
без ESLint — не ловит ошибки типов и Vue-правила.

### 12. Отложено: `vasichmen/*`, Passport, шрифты, реальные острова

**Решение.** Пакеты `vasichmen/laravel-foundation` и `laravel-handbooks` подключаются вместе
с первой сущностью/справочником; Passport — с первым закрытым API; WOFF2-шрифты — с реальной
вёрсткой; реальные острова — отдельными change'ами.

**Почему.** Каркас не должен тянуть неиспользуемые зависимости, пустые конфиги и риск
несовместимости версий. Ни одна дельта этого change их не требует.

**Альтернативы.** Подключить всё сразу — увеличивает поверхность настройки и проверок без
пользы для «пустой главной».

## Risks / Trade-offs

- **`@vite` падает, если нет ни manifest, ни `public/hot`** → ошибка намеренная: она
  сигнализирует, что не выполнен `npm run build` или не запущен `npm run dev`. В деплое
  сборка обязательна; в dev — `composer dev`.
- **Устаревший `public/hot` после остановки Vite** → страница ссылается на мёртвый dev-сервер.
  Файл в `.gitignore`, Vite удаляет его при штатном завершении; при проблеме удалить вручную,
  `composer dev` перезапускает Vite.
- **Production-ассеты не покрыты Playwright** (R-QA-2 требует тестов на dev) → в проверку
  входит `npm run build` и smoke-запуск `php artisan serve` без `public/hot`; полноценный
  production-прогон — задача CI.
- **Проверочный остров — временный код** → он изолирован в `resources/js/islands/` и реестре,
  удаляется вместе с первым реальным островом; не несёт бизнес-логики.
- **DB-проверка работает только в `local`** → в production недоступность БД даст общую
  ошибку, а не диагностическую страницу. Это осознанно: требование относится к локальному
  запуску, а production-диагностика — отдельная задача мониторинга.
- **`getPdo()` может ждать при недоступном удалённом хосте** → ТЗ использует `127.0.0.1`,
  где отказ приходит сразу; при переходе на удалённую БД понадобится connect timeout.
- **Слияние скелета может затереть проектные файлы** → скелет ставится в temp, переносится
  по явному списку, проектные `AGENTS.md`, `rules.md`, `docs/`, `openspec/`, `.gitignore`
  сохраняются; diff проверяется до коммита.
- **`artisan dev` автоматически перезапускает упавший процесс** → сломанный Vite может
  перезапускаться в цикле; помогает чтение логов и `--no-restart` при необходимости.
- **Inline-CSS на страницах ошибок расходится с дизайн-системой** → принято для каркаса;
  после появления реальных токенов и вёрстки страницы ошибок можно перевести на общий layout.
- **File-сессии не работают между несколькими экземплярами приложения** → сейчас один
  локальный узел; production-драйвер выбирается отдельно (см. Open Questions).
- **Playwright требует доступной БД**, потому что сервер работает в `local` → это соответствует
  сценарию локального запуска; `globalSetup` сообщит, если страница недоступна.

## Migration Plan

Данных и доменной схемы нет, поэтому миграция сводится к первичному развёртыванию каркаса.

1. Поставить скелет Laravel 13 во временный каталог, слить с проектом, сохранив существующие
   файлы и правила `.gitignore`.
2. Настроить `.env.example` (pgsql, file/sync-драйверы, `APP_LOCALE=ru`, `APP_URL`), выполнить
   `composer install`, `npm install`, `php artisan key:generate`.
3. Добавить роуты, `PageController`, layout, meta-партиал, страницы, 404 и страницу ошибки БД.
4. Добавить `app.ts`, реестр, проверочный остров, `vite.config.ts`, `app.css` + `tokens.css`.
5. Настроить TypeScript strict, ESLint/Prettier, PHPStan/Larastan, Playwright и тестовые
   сценарии.
6. Проверить: `php artisan route:list`, `npm run build`, `npm run lint`, `npm run typecheck`,
   `./vendor/bin/pint --test`, `./vendor/bin/phpstan analyse`, `npm run test:e2e` на
   запущенном `composer dev`.
7. Вручную: открыть `/`, `/about`, `/preorder`, `/how-to-order`, `/contacts`, `/no-such-page`;
   остановить PostgreSQL и убедиться, что страница отдаёт диагностическое сообщение; выполнить
   production smoke без `public/hot`.

**Rollback.** Изменение не создаёт таблиц и не пишет данных. Откат — revert коммита/ветки;
`public/build` и `node_modules` регенерируются, `vendor` переустанавливается, внешних
состояний нет. Первый коммит и пуш — только по явной просьбе пользователя.

## Open Questions
