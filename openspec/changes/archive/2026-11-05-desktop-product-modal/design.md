# Design

## Context

Фаза 4 уже отдаёт десктопную колонку серверным HTML: карточки рисует Blade
(`catalog.card`), карусель — остров-контроллер, данные приходят из `HomePageResource`.
Серверная часть прямой ссылки тоже готова: `HomePageRequest` принимает `product`,
`HomePageService` находит товар по slug (включая `out` и товар другого сезона), а
`HomePageResource` отдаёт ключ `product` с полным `ProductResource`. В `home.blade.php`
этот ключ пока не используется, карточка неинтерактивна, окна товара нет.

Что именно нужно сделать, описано в `proposal.md` и `specs/product-modal/spec.md`;
ниже — только технические решения, которые нужны, чтобы выполнить требования.

Ограничения, задающие подход:

- Blade отвечает за индексируемый контент, Vue — только острова; данные острова
  приходят пропсами из HTML (`AGENTS.md` §5.10, `client-islands`).
- Vue — только Options API, TypeScript strict, внешние данные проверяются zod.
- Новый JSON-API, миграции и изменения `ProductResource` не нужны: все поля товара
  уже есть в page-ресурсе.
- Форматирование цены, надзаголовка и подписей статусов — задача слоя отображения
  (Blade/Vue), ресурсы отдают сырые значения.
- Слои и движение заданы токенами: затемнение `--z-overlay` (30), диалог
  `--z-dialog` (31), `--dur-slow` (400 ms), `--dur-base` (250 ms), `--ease-standard`,
  `--ease-exit`, `--radius-modal-arch-desktop`, `--size-modal-width`, `--color-overlay`.
- Фаза только десктопная (от 1200 px); мобильная шторка — отдельная фаза.
- Playwright работает на поднятом `composer dev`; feature-тесты — только на дорогое.

## Goals / Non-Goals

**Goals:**

- Открывать окно из карточки мышью, Enter и Space, а также по прямой ссылке
  `?product=…`, включая товар вне наличия и товар другого сезона.
- Оставить единственный источник данных — серверный page-ресурс; остров не делает
  запросов и не дублирует правила выдачи товаров.
- Сделать окно полноценным модальным слоем: история, фокус-ловушка, `inert` фона,
  блокировка прокрутки, возврат фокуса, закрытие крестиком, Escape и кликом мимо.
- Воспроизвести FLIP-анимацию из карточки и обратно, сохранив уменьшенное движение.
- Зафиксировать контракт острова и карточки так, чтобы его можно было проверить
  feature- и Playwright-тестами.

**Non-Goals:**

- Мобильная шторка, свайп-закрытие, «Отложить», счётчик количества и корзина.
- Новый JSON-эндпоинт, клиентская загрузка товара, состояния загрузки/ошибки
  «Отложить» из кадров handoff (в MVP действия «Отложить» нет).
- Изменение правил выдачи сезона/товаров и состава `ProductResource`.
- Общая система модальных окон для меню/будущих слоёв; в этой фазе — один остров окна.
- Работа окна без JavaScript: без JS карточка остаётся обычной ссылкой на `?product=…`,
  но само окно — клиентское поведение.

## Decisions

### 1. Карточка остаётся Blade-разметкой, интерактивность даёт ссылка-оверлей

**Решение.** `<li class="catalog-card">` сохраняет роль ячейки сетки и все текущие
классы/анимации. Внутрь добавляется пустая ссылка `.catalog-card__link` с
`position: absolute; inset: 0`, `aria-label="Открыть товар «{name}»"`,
`aria-haspopup="dialog"`, `data-product-modal` и `data-product-slug`. `href` собирается
на сервере через `request()->fullUrlWithQuery(['product' => $slug])`, поэтому сохраняет
`season`, `cat` и остальные параметры. Enter обрабатывается нативно как клик по ссылке;
для Space добавляется делегированный `keydown` с `preventDefault`. Фокус-кольцо Honey
рисуется на ссылке, то есть по форме карточки.

**Почему.** Это сохраняет одну реализацию карточки и весь серверный контент, даёт
нативную семантику ссылки, клавиатуру и осмысленный fallback без JS. Не нужно переносить
внутреннюю разметку карточки в `<a>` (внутри `<ul>` это невалидно, а перенос классов
потянет переделку сетки и существующих тестов) и не нужно вручную эмулировать кнопку
через `role="button"`.

**Альтернативы.** Обернуть всё содержимое карточки в `<a>` и превратить `li` в
обёртку — потребует перенести поверхность, hover и `--card-index` на новый элемент,
сломает существующие селекторы и тесты. Сделать `li` кнопкой через `role="button"` —
потеряется нативный `href` и fallback, придётся вручную обрабатывать Enter/Space.
Клик по `li` без ссылки — то же, но ещё и без доступного имени.

### 2. Один page-level остров окна, смонтированный вне `<main>`

**Решение.** В `layouts/app.blade.php` после `</main>` добавляется `@stack('overlays')`.
Главная кладёт туда Blade-компонент `x-product-modal`, который рендерит пустой контейнер
`<div data-island="product-modal" data-props='…'></div>`. Остров один на страницу и
монтируется общим `app.ts`; вложенных островов нет. Повторное открытие при уже открытом
окне игнорируется, поэтому второй слой не создаётся.

**Почему.** При открытом окне фон должен стать `inert`, а окно — остаться доступным.
Если смонтировать остров внутри `main` или колонки, `inert` на предка сделает
недоступным и само окно. Отдельный стек над `main` решает это без ручного перебора
соседей и не меняет контракт `client-islands`: `mount()` по-прежнему затирает только
свой контейнер.

**Альтернативы.** Остров внутри `catalog-column` или `main` — нельзя инертить фон.
Остров на каждую карточку — несколько экземпляров диалога, нарушение «один слой
одновременно» и лишние подписки. Телепортировать DOM в `body` из Vue — лишняя
механика при уже готовом стеке.

### 3. Данные окна — props из page-ресурса, без нового API и Resource

**Решение.** Blade собирает пропсы:

```text
products:        $page['desktop_products']   // карточки текущего сезона
initial_product: $page['product']            // результат ?product=…, может быть null
preorder_url:    route('preorder')
```

Схема zod описывает только нужные окну поля: `slug`, `name`, `story_title`,
`description`, `pack`, `facts`, `price`, `price_unit`, `status`, `stock`, `icon`,
`category.name`, `harvest`. Неизвестные ключи отбрасываются. `initial_product`
передаётся отдельно, потому что товар по прямой ссылке может не входить в
`desktop_products` (статус `out`, девятая карточка, другой сезон).

**Почему.** Все данные уже есть в `HomePageResource`, а `HomePageService` уже умеет
разрешать `product` по slug, включая `out`. Это сохраняет единственный источник истины
и не добавляет клиентских состояний загрузки. Дублирование одного товара в
`initial_product` и в массиве `products` ограничено одной записью и не влияет на
контракт.

**Альтернативы.** Новый `/api/v1/product` — запрещён объёмом change'а и дублирует
серверную выдачу. Отдельный `ProductModalResource` — те же поля, ради которых не нужен
новый класс. Складывать полный JSON товара в `data-product` каждой карточки —
размазывает контракт по разметке и усложняет схему; массив из восьми товаров в
`data-props` предсказуемее.

### 4. История: синтетическая базовая запись для прямой ссылки и `history.back()` на закрытие

**Решение.** Открытие из карточки: `history.pushState({ productModal: true }, '', href)`,
где `href` уже содержит `product` и остальные параметры.

Прямая ссылка: при старте, если `initial_product` существует и `history.state` ещё не
помечен как состояние окна, текущая запись переписывается на тот же URL без `product`
(`replaceState`), затем сразу добавляется запись с `product` (`pushState`). Так у окна,
открытого по ссылке, тоже есть предыдущая запись на этой же странице; повторная
инициализация после reload/bfcache синтетическую запись не дублирует.

`popstate` — единственный источник синхронизации с URL: если в адресе есть известный
`product`, окно открывается/обновляется; если параметра нет или товар неизвестен,
окно закрывается. Крестик, Escape и клик по затемнению вызывают `history.back()`;
`popstate` запускает анимацию закрытия. Если состояние истории не наше
(`history.state?.productModal` не выставлен), закрытие делает `replaceState` без
`product` и анимацию, чтобы не уйти со страницы.

**Почему.** Это единообразно закрывает окно и из карточки, и по прямой ссылке, сохраняет
все query-параметры и выполняет требование ТЗ §12: открытие — `pushState`, «Назад» и
крестик — через историю, окно не остаётся в истории текущей страницы. Синтетическая
базовая запись нужна только для прямого захода, иначе `history.back()` увёл бы на
предыдущий сайт.

**Альтернативы.** Для прямой ссылки закрывать через `replaceState` — проще, но
поведение крестика отличалось бы от карточки и расходилось с ТЗ. Не добавлять базовую
запись — «Назад» после прямого захода покидал бы страницу. SPA-роутер — запрещён
(`AGENTS.md` §2).

### 5. Модальный слой: явный overlay + `role="dialog"`, а не нативный `<dialog>`

**Решение.** Остров рендерит фиксированный overlay на весь вьюпорт (`--color-overlay`,
`--z-overlay`) и панель 520 px над ним (`--z-dialog`). Панель получает
`role="dialog"`, `aria-modal="true"`, `aria-labelledby` на заголовок и
`aria-describedby` на описание. Крестик — кнопка 44 × 44 с `aria-label="Закрыть"`.
При открытии фокус переходит на крестик; Tab/Shift+Tab зацикливаются внутри панели
(список focusable-элементов пересчитывается при открытии). `header.site-header` и
`main.site-main` получают `inert`; прокрутка страницы выключается классом на `<html>`
с компенсацией ширины скроллбара. После закрытия фокус возвращается на ссылку-источник,
а если её нет — на H1 сезона (`tabindex="-1"` уже есть).

**Почему.** Явный overlay позволяет использовать заданные токены слоёв и полностью
контролировать FLIP, клик по затемнению и закрытие через историю. Нативный `<dialog>` с
`showModal()` даёт хорошую базу, но переносит элемент в top layer и обходит
задокументированные `z-index`, а его `::backdrop` и `cancel` требуют отдельной
интеграции с `history.back()` и анимацией. Ручная ловушка фокуса небольшая и
переиспользуема для меню в следующей фазе.

**Альтернативы.** `<dialog>` + `showModal` — меньше кода для фокуса, но другой контракт
слоёв и закрытия. Готовая библиотека модалок — новая зависимость и лишний вес ради
одного окна.

### 6. FLIP-анимация через Web Animations API

**Решение.** Перед открытием запоминается `DOMRect` карточки-источника (для прямой
ссылки — видимая карточка с тем же `data-product-slug`, если она есть). После
монтирования панели измеряется её итоговый `DOMRect`; панель анимируется от
`translate + scale` карточки к своему месту за `--dur-slow` с `--ease-standard`,
затемнение — по прозрачности. Закрытие — обратный переход к карточке за `--dur-base`
с `--ease-exit`, затемнение гаснет вместе с панелью. Анимируются только `transform`
и `opacity`; после завершения инлайновые стили снимаются, содержимое размонтируется.

Если карточки-источника нет (товар `out` или карточка вне вьюпорта), окно раскрывается
из центра лёгким масштабом и прозрачностью. При `prefers-reduced-motion: reduce`
геометрия не считается: остаётся только `opacity` 150 ms, длительность закрытия
уменьшается до 150 ms.

**Почему.** Геометрия карточки и окна динамическая, а CSS-keyframes не умеют
подставлять произвольный прямоугольник. WAAPI даёт отменяемую анимацию без layout-
свойств и без ручных таймеров на каждый кадр. Требования §14.5 (400/250 ms) и
уменьшенное движение выполняются явно.

**Альтернативы.** Анимировать `top/left/width/height` — дорого и даёт дрожание.
Фиксированный `scale(0.2)` из центра — не «из карточки». `document.startViewTransition`
— не во всех браузерах и относится к фазе 9.

### 7. Содержимое и форматирование окна

**Решение.** Заголовок — `story_title ?? name` (в кадре это «Антоновка с дедушкиной
яблони», а `name` — короткое «Антоновка»). Надзаголовок — `category.name` плюс
` · сбор {harvest}`, если сбор задан; регистр поднимается CSS. Описание — обычный
текст, факты — отдельные чипы; при пустом списке блок фактов не выводится. Цена
форматируется на клиенте модулем `format-price.ts` по тем же правилам, что Blade:
целые рубли, неразрывный пробел в тысячах, `₽` или `₽/кг` по `price_unit.id`.
Ссылка предзаказа приходит пропсом `preorder_url`, чтобы не дублировать имя роута
в TypeScript.

**Почему.** Это соответствует ТЗ §7.3 и кадру, а форматирование остаётся на слое
отображения, как требует `AGENTS.md`. Отдельный TS-модуль нужен только острову; Blade-
компонент цены не меняется, небольшая дублирующая логика цены зафиксирована тестами.

**Альтернативы.** Использовать `name` в заголовке — расходится с кадром и полем
`story_title`. Отдавать `price_label` из ресурса — запрещено. Переиспользовать
Blade-компонент цены внутри Vue — невозможно без второго рендерера.

### 8. Статусы наличия и отсутствие действий корзины

**Решение.** `in_stock` — без бейджа и без кнопки. `few` — бейдж «осталось {stock}»
(или «осталось мало», если остатка нет) рядом с ценой, без кнопки. `preorder` —
бейдж «предзаказ» и золотая кнопка во всю ширину «Записаться на предзаказ»,
ссылка на `preorder_url`. `out` — приглушённые иллюстрация и цена, бейдж
«нет в наличии» и текст вместо кнопки: «Товар закончился в этом сезоне. Снова появится
в следующем сезоне.» Счётчика количества, кнопки «Отложить» и любых изменений товара
в окне нет.

**Почему.** Это правила §9.2 и §7.3. Для `out` в данных нет отдельного поля «когда
появится снова», поэтому используется нейтральная формулировка про следующий сезон;
это честно отражает имеющиеся данные и не вводит новую миграцию.

**Альтернативы.** Показывать цену у `out` как обычную — противоречит §9.2. Кнопка
«Отложить» и степпер из кадров — прямо исключены ТЗ (В1, В10). Добавлять поле
`out_note` в товар — вне объёма change'а.

### 9. Окно работает только на десктопе

**Решение.** Остров проверяет `matchMedia('(min-width: 1200px)')` перед открытием и не
создаёт синтетическую историю на мобильном. При переходе через брейкпоинт во время
открытого окна оно закрывается, блокировка прокрутки снимается. На мобильном прямая
ссылка `?product=…` остаётся в адресе, но окно не открывается: шторка — фаза 8.

**Почему.** Фаза 5 — десктопная, а мобильная шторка имеет другую геометрию, жесты и
поведение. Открывать десктопное окно на телефоне значило бы временную вёрстку, которую
придётся выбрасывать.

**Альтернативы.** Открывать окно и на мобильном — конфликт с будущей шторкой и лишняя
адаптация. Скрывать окно только CSS, оставляя блокировку прокрутки и `inert` — «мёртвая»
страница на телефоне.

### 10. Контракт проверок

**Решение.** Feature-тесты проверяют: карточка содержит ссылку с правильным `href` и
атрибутами; страница с `?product=antonovka` отдаёт контейнер `product-modal` с
`initial_product`; `?product=kartofel` отдаёт `out`-товар; неизвестный slug не даёт
товара в пропсах. Playwright проверяет открытие мышью/Enter/Space, прямую ссылку,
`out`, предзаказ, закрытие крестиком/Escape/кликом мимо, «Назад», возврат фокуса,
фокус-ловушку, блокировку прокрутки, высоту и скролл описания, FLIP-длительности и
`prefers-reduced-motion`. Существующие тесты карточки обновляются: в карточке теперь
есть `<a>`, но она по-прежнему остаётся `<li class="catalog-card">`.

**Почему.** Анимации и история — самое хрупкое; их нужно проверять по поведению
(длительности `getAnimations`, `history.state`, `activeElement`), а не скриншотами.

## Risks / Trade-offs

- **Синтетическая запись истории и `popstate` могут рассинхронизироваться** → окно
  открыто, а URL уже без `product`. Митигация: единый обработчик `popstate` читает URL
  как источник истины; при закрытии ставится флаг `closing`; если состояние истории не
  наше, используется `replaceState`, а не `back()`. Тесты на deep link + Back + крестик.
- **FLIP из арочной карточки в арочное окно может выглядеть как «сплющивание»** →
  контент на 400 ms масштабируется вместе с панелью. Митигация: `transform-origin` в
  центре, анимация только `transform/opacity`, при `prefers-reduced-motion` — только
  прозрачность; визуальная сверка с кадром и быстрый откат к fade-only при проблеме.
- **Дублирование JSON товаров в `data-props`** → страница тяжелее на восемь описаний.
  Митигация: только `desktop_products` (не весь мобильный список), zod отбрасывает
  лишние поля; дублирование ограничено и не требует запроса.
- **`out`-товар не содержит даты возврата** → текст будет общим. Митигация:
  нейтральная формулировка «в следующем сезоне»; при появлении требования точной даты
  — отдельное поле в данных, не меняющее контракт окна.
- **Блокировка прокрутки и `inert` могут «залипнуть» при ошибке/размонтировании** →
  страница останется заблокированной. Митигация: снятие класса, `inert` и слушателей
  в `beforeUnmount` и после завершения закрытия; тест на прокрутку и фокус после
  закрытия всеми способами.
- **Ссылка-оверлей перекрывает содержимое карточки** → нельзя выделить текст, но
  других интерактивных элементов в карточке нет. Митигация: `aria-label` содержит
  название, визуальный фокус на ссылке; hover/анимации остаются на `li`.
- **`inert` не во всех старых браузерах** → фон может оставаться фокусируемым.
  Митигация: ручная фокус-ловушка и проверка `focusin`; целевой десктопный Chromium
  Playwright поддерживает `inert`.
- **Неизвестный `product` остаётся в адресе** → окно не открывается, но URL выглядит
  «товарным». Митигация: страница остаётся обычной, параметр не ломает выборку; при
  необходимости его можно убрать позже, не меняя контракт окна.
- **Прямая ссылка на телефоне не открывает окно** → пользователь видит обычную
  главную. Митигация: это осознанный объём фазы 5; шторка придёт в фазе 8, URL и
  серверная выдача уже готовы.
- **Тесты анимации нестабильны во времени** → митигация: проверять
  `element.getAnimations()`/`animation.effect.getTiming().duration`, а не ждать
  фиксированные миллисекунды; reduced motion проверять отдельно.
