# Design

## Context

Колесо года — первая реальная поверхность главной. К началу change'а в репозитории уже есть
домен фазы 2: `HomePageService`, `HomePageDTO`, `HomePageResource`, `SeasonResource`,
`ProductResource`, сидеры сезонов и товаров, токены колеса и `--wheel`. При этом HTTP-слой
главной ещё не подключён: `PageController::home()` отдаёт заглушку, данные каталога в Blade
не попадают. `scaffold-probe` — единственный зарегистрированный остров; рантайм островов
(`app.ts`, `data-props`, монтирование по разметке) уже работает. В `package.json` нет `zod`,
хотя стек проекта его предполагает.

Ограничения, которые определяют подход:

- Blade отдаёт контент, Vue — только острова; Options API, один entry-point, без `vue-router`,
  Inertia и SSR (`AGENTS.md` §2, §5.10; `rules.md` R-FE).
- Переходы — обычные `<a href>` и серверные маршруты (R-FE-7). Сезон — часть серверного
  состояния страницы, а не только клиентского.
- Backend отдаёт сырые значения; месяц пользователя и часовой пояс вычисляются на клиенте
  (R-ARCH-13). Сервер не подставляет свой месяц.
- Данные и API фазы 2 не переделываются: новых таблиц, полей БД и JSON-эндпоинтов нет.
- Колесо — только десктоп от 1200 px. Телефон, правая колонка каталога, окно товара,
  мобильная лента и меню — следующие фазы.
- Playwright работает на поднятом `composer dev`; feature/unit-тесты — только на дорогое.

Мотивация — `proposal.md` («Why»), требования — `specs/season-wheel/spec.md`. Ниже — только
технические решения, которые нужны, чтобы эти требования выполнить.

## Goals / Non-Goals

**Goals:**

- Подключить главную к существующим сервису и ресурсам и отдать Blade данные колеса.
- Сделать выбор сезона серверным (`?season=`), а остров — усилением: поворот, hover,
  перетаскивание, клавиатура, доступность, reduced motion.
- Зафиксировать контракт props колеса, типы и проверку данных (`zod`) до реализации.
- Сохранить работу без JavaScript: подписи сезонов и ссылки остаются в серверном HTML.
- Удалить `scaffold-probe` и его стили, не меняя механику монтирования островов.

**Non-Goals:**

- Правая колонка, карточки, карусель, окно товара, мобильная лента, фильтр и меню.
- Новые сущности, миграции, JSON API, справочники и изменения правил выдачи сезона/товаров.
- Полная смена сезона без перезагрузки страницы и клиентская «сцена» сезона — фаза 9.
- Посезонные `title`/`description`/`canonical` и JSON-LD — фаза 11.
- Пиксельная сверка и приёмка остальных сезонов — фазы 10 и 13.
- Визуально точное колесо без JavaScript: fallback остаётся семантическим списком сезонов.

## Decisions

### 1. Выбор сезона — настоящая серверная навигация, остров только усиливает

**Решение.** Каждый сектор — ссылка `/?season={slug}`. Клик, `←/→`, `Home/End` и завершение
перетаскивания ведут на серверную страницу выбранного сезона. Остров не подменяет навигацию
на `replaceState`: перед уходом он кладёт в `sessionStorage` текущий угол, целевой сезон
и намерение вернуть фокус, а новая страница проигрывает поворот от этого угла к целевому
за 700 ms и после монтирования возвращает фокус на активную вкладку. Если перехода из
колеса не было, при первом заходе в сессию колесо проявляется и доворачивается на 20°
(§14.2 ТЗ). Модифицированные клики (Ctrl/Cmd/Shift/Alt, средняя кнопка) не перехватываются.
Клик по уже активному сектору навигацию не запускает.

**Почему.** R-FE-7 и §16.1 ТЗ требуют настоящих ссылок и серверного контента; SPA-переход
запрещён. Такой подход сразу даёт рабочий URL, корректный серверный фон и будущую правую
колонку, а анимация остаётся непрерывной за счёт переданного угла.

**Альтернативы.** Клиентский `replaceState` без перезагрузки — колесо меняется, но серверный
контент (фон, H1, каталог фазы 4) остаётся от прежнего сезона. Задержка навигации до конца
анимации — 700 ms «мёртвого» ожидания и риск потерять переход. View Transitions — возможное
улучшение фазы 9, но не базовая механика этого change'а.

### 2. HTTP-слой главной: Request/DTO, тонкий контроллер, page-ресурс и отдельные props колеса

**Решение.** `PageController::home()` принимает `HomePageRequest` с DTO (`season`, `product`,
`month`), вызывает `HomePageService::getHomePage()` и оборачивает DTO в `HomePageResource`.
В ресурсе появляется секция `wheel` — минимальный контракт для острова, а не копия всей
страницы. В `HomePageDTO` добавляется `seasonProductsCounts` (число видимых товаров по
сезонам); `SeasonResource` получает `products_count`. Это нужно колесу для «ПОКА ПУСТО»
и для вежливого объявления «Осень, 8 продуктов». Blade передаёт `@json($page['wheel'])`
в `data-props` и рендерит серверный fallback из тех же данных. `body[data-season]` берётся
из активного сезона страницы.

Правила Request: `season` и `product` — nullable-строки с ограничением длины, `month` —
nullable-целое. Неизвестный сезон или товар не являются ошибкой валидации: сервис уже умеет
делать fallback на сезон по месяцу/первый по порядку и возвращать `null` для товара.

**Почему.** Валидация должна жить в Request (R-REQ-1), контроллер — оставаться тонким,
а props — быть проверяемым серверным контрактом, а не вычисляться в Blade. `products_count`
уже фактически считается сервисом; его нужно только довести до ресурса, не добавляя запросов.

**Альтернативы.** Обойтись без Request и читать `$request->query()` в контроллере — нарушает
R-REQ-1 и R-ARCH-3. Собирать props в Blade из полного page-ресурса — переносит логику
в шаблон и раздувает JSON. Передавать в остров весь `HomePageResource` — лишние данные
и связывание колеса с будущими блоками страницы.

Замечание по R-REQ-15: Request здесь не «на будущее», а для реальных query-параметров
страницы; правило запрещает спекулятивные Request-классы, а не валидацию фактического ввода.

### 3. Геометрия и порядок колеса фиксируются в одном месте

**Решение.** SVG: `viewBox="-350 -350 700 700"`, вращается одна группа — сектора, кольцо
месяцев и засечки; центр неподвижен. Базовые единицы:

| Элемент | Значение |
|---|---|
| Сектор | кольцо 130–288, зазор 1.2° |
| Подпись сезона | r = 190 |
| Центры иконок | r = 252, шаг 19° |
| Кружок активного / неактивного сектора | 50 / 40 ед. |
| Иконка | 76 % диаметра кружка |
| Подписи месяцев | r = 314 |
| Засечки | 296–332 |
| Точка текущего месяца | r = 346 |
| Центр | r = 118 |

Порядок колеса — константа `summer → autumn → winter → spring`, а не `sort_order` из БД:
сидеры упорядочены `spring → summer → autumn → winter` для годовой цепочки, а колесо
требует другого начала. Целевой угол активного сезона: `-(index - 1) * 90°`, поэтому осень
(индекс 1) стоит справа. При переходе выбирается ближайший эквивалентный угол `target + 360k`,
чтобы колесо шло по кругу без границ и не делало лишний оборот.

**Почему.** Явная константа защищает от случайной зависимости от `sort_order` и делает
порядок проверяемым. Геометрия в единицах `viewBox` масштабируется вместе с `--wheel`.
Цвета, прозрачности и тайминги берутся из токенов; в SVG используются CSS-переменные,
литералами остаются только единицы геометрии. Активный сектор показывает до четырёх иконок,
неактивный — первые три; при `products_count = 0` подпись заменяется на «ПОКА ПУСТО»,
иконок нет.

**Альтернативы.** Выводить порядок из `sort_order` — легко получить неверное начало и
сломать требование «лето → осень → зима → весна». Считать позиции в пикселях — не
масштабируется на 1200–1920.

### 4. Вращение: одно числовое состояние и RAF, контр-вращение подписей и иконок

**Решение.** В острове есть одно состояние `rotation`. Анимация доводки — `requestAnimationFrame`
с функцией cubic-bezier `0.34, 1.56, 0.64, 1`; на каждом кадре из `rotation` выводятся
позиции секторов, засечек, подписей месяцев и иконок. Подписи сезонов и иконки получают
локальный `rotate(-rotation)` вокруг своей точки — остаются прямыми в любом положении.
Подписи месяцев идут по касательной к кольцу; переворот на 180° выбирается по целевому углу
(90–270°) один раз в конце, как в Д4. Во время drag `rotation` меняется напрямую без
анимации; после отпускания — доводка к ближайшему сезону. При reduced motion `rotation`
ставится мгновенно, остаётся только opacity 150 ms.

**Почему.** Контр-вращение подписей и иконок и переворот месяцев должны быть согласованы
с углом в каждом кадре. Одно состояние и RAF дают это без рассинхронизации и без зависимости
от `@property`/CSS-переменных в SVG.

**Альтернативы.** CSS-transition на группе плюс контр-вращение детей — трудно синхронизировать
в Safari и при drag. Web Animations API на группе и каждом ребёнке — больше кода и всё равно
не решает переворот месяцев. Анимация `left/top` — запрещена правилами движения.

### 5. Контракт props, `zod` и доставка иконок

**Решение.** В `data-props` уходит только нужное колесу:

```json
{
  "active_season": "autumn",
  "seasons": [
    {
      "slug": "autumn",
      "name": "Осень",
      "sub": "УРОЖАЙ",
      "url": "/?season=autumn",
      "products_count": 9,
      "products": [{ "name": "Антоновка", "icon": "product-apples.svg" }]
    }
  ]
}
```

Ключи — `snake_case`, как в остальном JSON проекта. `app.ts` передаёт острову один prop
`data`; схема `zod` в `resources/js/types/season-wheel.ts` проверяет форму, наличие четырёх
уникальных slug из `WHEEL_ORDER`, `sub` не длиннее 7 знаков и `products_count >= 0`.
Невалидные данные — `console.error` и пропуск монтирования; серверный fallback остаётся.
`url` формирует HTTP-слой (page-ресурс) через `route('home', ['season' => ...])`, чтобы
остров не знал маршрутов.

Иконки: `scripts/build-icons.mjs` вместе с Blade-партиалами генерирует
`resources/js/generated/product-icons.json` — внутренности очищенных SVGO иконок по имени
без префикса `product-`. Остров импортирует этот JSON-модуль и нормализует
`product-apples.svg` в `apples`. Сгенерированный файл коммитится, как и Blade-партиалы,
чтобы `vue-tsc` работал на чистом checkout; `npm run dev`/`build` пересобирают его через
`icons:build`; из Prettier он исключается как сгенерированный. Логотип в центре —
`<image href="/brand/logo-lockup-on-dark-outlined.svg">` из уже собираемого `public/brand`.

**Почему.** Минимальный props не раздувает HTML и не связывает колесо с будущими блоками.
Иконки остаются одним источником с Blade-партиалами, без ручного дублирования 29 SVG,
и проходят ту же очистку SVGO, что и остальные ассеты. `zod` ловит расхождение контракта
до отрисовки, а не в середине шаблона.

**Альтернативы.** Импортировать исходные SVG через `import.meta.glob('?raw')` — проще,
но обходит SVGO и проверку метаданных: при следующей синхронизации handoff в бандл может
попасть C2PA. Передавать готовую SVG-разметку в props — +16–20 КБ JSON на страницу
и дублирование данных. Отдельный SVG-спрайт — ещё один шаг пайплайна; можно сделать позже,
если вес бандла станет проблемой. Валидация вручную type-guard'ами — проект уже использует
`zod`.

### 6. Доступность и модель ввода

**Решение.** Сектора — `<a role="tab">` внутри `role="tablist" aria-label="Сезоны"`;
у активного `aria-selected="true"` и `tabindex="0"`, у остальных — `-1` (roving tabindex).
`aria-label` сектора содержит название сезона и перечень его товаров на колесе; для пустого
сезона — «пока пусто». Иконки — `aria-hidden`, без `tabindex`. Смена сезона объявляется
вежливым `aria-live="polite"`; текст — сезон и число продуктов со склонением через
`Intl.PluralRules('ru')`. Фокус-обводка показывается только при `:focus-visible` и рисуется
по форме сектора: Honey 3 ед. поверх тёмного контура 5 ед., чтобы обводка читалась и на
кремовом активном секторе, и на тёмных.

Клавиши: `←/→` — предыдущий/следующий по `WHEEL_ORDER`, `Home` — лето, `End` — весна,
по кругу. Drag — Pointer Events с захватом указателя; движение больше порога подавляет
последующий клик. Горизонтальный жест тачпада не перехватывается: слушаем `pointerdown`,
а не `wheel`/`touchstart`, и не вызываем `preventDefault` для прокрутки. Hover и tooltip —
только `@media (hover: hover)`; задержка 300 ms, позиция считается по `getBoundingClientRect`
иконки и прижимается внутрь колеса. На тач-экране тап по иконке — обычный переход по ссылке
сектора.

**Почему.** Это прямое покрытие §13 и §14.4 ТЗ: вкладки, список товаров в имени, live-регион,
фокус только на секторах, отсутствие tooltip на тач-экране.

**Альтернативы.** HTML-кнопки поверх SVG — проще семантика, но фокус-обводка по форме сектора
и точные зоны нажатия требуют дублирования геометрии. Все сектора в порядке Tab — противоречит
паттерну вкладок; иконки в фокусе — запрещены требованием. Tooltip в SVG — сложнее измерять
текст и слой.

### 7. Локальный месяц, год и стартовый сезон

**Решение.** Сервер не вычисляет месяц. Если в адресе нет `season`, крошечный inline-скрипт
в `<head>` главной определяет локальный месяц, переводит его в slug и делает
`location.replace` на `?season=...`, сохраняя остальные параметры. Скрипт стоит в head,
поэтому пользователь не видит промежуточный сезон и неверный фон. Если `season` уже есть,
скрипт ничего не делает; параметр `month` (для программных запросов и тестов) скрипт
не перебивает. Остров вычисляет текущий месяц для маркера на кольце и текущий год для центра.

**Почему.** Часовой пояс знает только клиент, а серверный HTML (фон, будущая колонка) должен
сразу соответствовать выбранному сезону. Редирект до отрисовки — самый простой способ
сохранить серверное состояние без cookie и без клиентской сцены.

**Альтернативы.** Остров меняет сезон через `replaceState` — тогда `body[data-season]`
и серверный контент остаются от другого сезона, а острову пришлось бы менять DOM вне
контейнера, что противоречит `client-islands`. Передавать `month` в props с сервера —
запрещено R-ARCH-13. Cookie с часовым поясом — не решает первый запрос.

### 8. Fallback без JavaScript и мобильный список сезонов

**Решение.** Blade рендерит внутри контейнера острова семантический `<nav aria-label="Сезоны">`
с четырьмя ссылками, названиями сезонов и подписями `sub` (или «ПОКА ПУСТО»). Без JS это
и есть рабочая навигация. После успешного монтирования Vue заменяет её колесом; в шаблоне
острова есть такой же список для ширины меньше 1200 px, где колеса нет. На десктопе колесо
занимает первую колонку существующего `.desktop-grid`; вторая колонка остаётся пустой до
фазы 4, а ниже 1200 px сетка не применяется. Контейнер резервирует размер `--wheel`, чтобы
не было CLS; при ошибке props/монтирования серверный fallback остаётся.

**Почему.** Не дублируем SVG-геометрию в Blade и сохраняем требование «без скриптов подписи
и ссылки работают». Мобильная главная не остаётся пустой до фазы 7. Основной SEO-контент
(H1 и заглушка) остаётся вне контейнера острова; fallback-навигация — это представление
самого острова без JavaScript, а не подмена контента страницы.

**Альтернативы.** Статическое SVG-колесо в Blade — второе место с геометрией и расчётом углов;
легко разойтись с островом. Оставить мобильную главную пустой — регресс относительно текущей
заглушки.

### 9. Заглушка главной сохраняется до фазы 4

**Решение.** Существующие `<h1>Усадьба Лыково</h1>` и текст «Здесь скоро появится главная
страница…» остаются в `home.blade.php` ниже колеса. Колесо добавляется отдельной секцией,
`scaffold-probe` удаляется. Правая колонка фазы 4 заменит заглушку и станет `tabpanel`.

**Почему.** Capability `site-shell` требует у главной один `h1` и текст заглушки в исходном
HTML; proposal не меняет эту capability. Удаление заглушки сейчас потребовало бы отдельной
дельты и сломало бы существующие проверки.

**Альтернативы.** Сразу отдать сезонный H1 и лид — это уже фаза 4, смешение объёма и лишняя
переделка.

## Risks / Trade-offs

- **Каждый выбор сезона — полная навигация** → на медленной сети колесо «моргает» и теряет
  фокус. Митигация: переход из колеса сохраняет угол и фокус в `sessionStorage`; новая
  страница возвращает фокус на активную вкладку и не проигрывает анимацию входа повторно;
  фаза 9 может заменить навигацию на клиентскую сцену.
- **Анимация перехода между документами может мигнуть** → колесо на новой странице сначала
  отрисовывается сервером/пустым контейнером. Митигация: контейнер резервирует `--wheel`,
  остров ставит стартовый угол до первого кадра анимации; запись `sessionStorage`
  одноразовая и с коротким сроком.
- **Стартовый редирект по локальному месяцу** → лишний запрос при первом заходе без
  `?season=`; при отключённом JS редиректа нет и остаётся серверный сезон по `sort_order`.
  Митигация: скрипт в `<head>` до отрисовки, поэтому промежуточный сезон не виден; no-JS
  сценарий явно описан и покрыт тестом.
- **Порядок колеса не совпадает с `sort_order`** → легко получить неверное начало.
  Митигация: константа `WHEEL_ORDER`, refine в `zod`, feature-тест на наличие всех четырёх
  slug и длины `sub` ≤ 7.
- **Контр-вращение и переворот месяцев** → сложная математика, ошибки на границах 90/270°.
  Митигация: одно состояние `rotation`, чистые функции углов, тесты на целевые углы всех
  четырёх сезонов и на переворот нижней половины; reduced motion обходит анимацию.
- **Иконки в бандле** → сгенерированный JSON-модуль тянет все 29 SVG (около 116 КБ исходно,
  меньше в gzip) на страницу. Митигация: приемлемо для MVP; при росте каталога — SVG-спрайт
  или генерация модуля только с нужными иконками.
- **`products_count` — добавление в page-ресурс** → контракт `HomePageResource`/`SeasonResource`
  расширяется. Митигация: поле аддитивное, не меняет БД и API; тесты фиксируют значения
  и используют его для пустого сектора и live-региона.
- **Удаление `scaffold-probe` ломает его e2e-тесты** → `client-islands.spec.ts` ссылается
  на проверочный остров. Митигация: тесты переписываются на реальный `season-wheel` с
  валидными props; проверки неизвестного имени и битого JSON остаются.
- **Главная теперь зависит от сидов** → без сезонов `HomePageService` бросает
  `SeasonNotFoundException` (500), тогда как раньше страница открывалась без БД. Митигация:
  `ExampleTest` и новые feature-тесты используют `RefreshDatabase` + `seed()`; локальная
  БД и `globalSetup` Playwright уже засеяны; риск отмечен для production-развёртывания.
- **Сектора — SVG-ссылки с `role="tab"`** → доступность SVG-ссылок в разных скринридерах
  может отличаться. Митигация: Playwright-проверки ролей, имён и порядка фокуса; при
  проблемах — гибрид с HTML-оверлеями без изменения геометрии и данных.
- **Пустой сектор в Playwright** → в сидах нет пустого сезона. Митигация: тест подменяет
  `data-props` в ответе (как уже делают тесты `client-islands`) и проверяет «ПОКА ПУСТО»
  без изменения production-данных.
- **Live-регион на новой странице** → некоторые скринридеры не объявляют текст, появившийся
  одновременно с регионом. Митигация: регион живёт в острове постоянно, текст обновляется
  после монтирования (следующий тик) из записи `sessionStorage`; проверка скринридером —
  в фазе 12, при необходимости регион можно поднять в Blade.
- **Текущий месяц в тестах** → зависит от даты и часового пояса. Митигация: Playwright
  фиксирует `Date` через `addInitScript`; маркер имеет тестовый атрибут.

## Migration Plan

1. Backend: добавить `HomePageRequest`/`HomePageRequestDTO` (`season`, `product`, `month`),
   подключить `HomePageService` в `PageController::home()`, добавить `seasonProductsCounts`
   в `HomePageDTO`, `products_count` в `SeasonResource` и секцию `wheel` в `HomePageResource`.
2. Blade/layout: вывести колесо отдельной секцией над существующей заглушкой, отдать
   `data-props`, серверный fallback-список сезонов, `body[data-season]` из активного сезона,
   inline-редирект по локальному месяцу в `<head>` (через стек), удалить `scaffold-probe`.
3. Frontend: добавить `zod`, типы и схему `resources/js/types/season-wheel.ts`, расширить
   `scripts/build-icons.mjs` генерацией `resources/js/generated/product-icons.json`
   и исключить её из Prettier, добавить `SeasonWheel.vue`, `season-wheel.css`,
   зарегистрировать остров, удалить `ScaffoldProbe.vue` и его CSS. `app.ts` начинает
   передавать острову `{ data }` и валидировать props по схеме.
4. Тесты: обновить `client-islands.spec.ts` и `ExampleTest`; добавить feature-тест props
   колеса и длины `sub`; добавить `tests/e2e/season-wheel.spec.ts` (клик, клавиатура,
   Home/End, drag, пустой сектор, доступное имя, live-регион, reduced motion, no-JS,
   текущий месяц).
5. Проверки: `php -l` по изменённым файлам, `php artisan route:list`, `./vendor/bin/pint --test`,
   `./vendor/bin/phpstan analyse`, `npm run lint`, `npx vue-tsc --noEmit`, `npm run build`,
   `npm run test:e2e` на `composer dev`. Визуально — 1440×900 и 1200×680, а также no-JS.
6. Миграций и изменений данных нет: используются уже засеянные сезоны и товары. После
   архивации change'а фаза 3 отмечается в `docs/plan/PLAN.md` по правилам `openspec/config.yaml`.

**Rollback.** Откат — revert коммита и `npm install` по восстановленному `package-lock.json`;
`npm run build` пересобирает ассеты. Таблицы и данные не меняются, `scaffold-probe`
возвращается вместе с прежним `home.blade.php`. Внешних состояний нет.

## Open Questions

- **Решено:** без-JS режим получает семантический список сезонов, а не статический макет
  колеса. Требования «подписи читаемы, ссылки работают» покрываются списком; визуальный
  паритет без JS, если понадобится, делается отдельной задачей после приёмки и не меняет
  контракт props и остров.
- Заменять ли в фазе 9 полную навигацию на View Transitions или клиентскую сцену сезона?
  Это не меняет текущие спеки, контракт `?season=` и разбиение задач; решение можно принять
  после появления правой колонки и состояний загрузки.
