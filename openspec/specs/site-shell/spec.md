# site-shell Specification

## Purpose
Отдаёт серверный HTML главной страницы и разделов-заглушек, чтобы сайт открывался по прямым адресам, был доступен без JavaScript и возвращал корректные HTTP-статусы.

## Requirements

### Requirement: Главная страница доступна по корневому адресу
Система SHALL отвечать на `GET /` статусом 200 и HTML-документом с сезонным заголовком первого уровня, лидом и товарами выбранного сезона на русском языке.

#### Scenario: Открытие главной страницы
- **WHEN** клиент запрашивает `GET /`
- **THEN** ответ имеет статус 200 и тип `text/html`
- **AND** в HTML присутствуют заголовок первого уровня, лид и товары выбранного сезона

#### Scenario: Главная страница без JavaScript
- **WHEN** клиент запрашивает `GET /` и не выполняет клиентские скрипты
- **THEN** заголовок первого уровня, лид, названия товаров, цены и статусы присутствуют в исходном HTML

#### Scenario: Заголовок первого уровня один
- **WHEN** клиент запрашивает `GET /`
- **THEN** в документе ровно один заголовок первого уровня

#### Scenario: Смена сезона меняет содержимое главной
- **WHEN** клиент запрашивает `GET /?season=winter`
- **THEN** заголовок первого уровня, лид и товары относятся к зимнему сезону

### Requirement: Разделы-заглушки доступны по прямым адресам
Система SHALL отдавать страницы-заглушки по адресам `/about`, `/preorder`, `/how-to-order`, `/contacts` со статусом 200, заголовком раздела, текстом-заглушкой и кнопкой «Назад», ведущей на главную. Каждая заглушка MUST использовать общую шапку и меню сайта и MUST иметь собственные `title` и `description`.

#### Scenario: Открытие раздела-заглушки
- **WHEN** клиент запрашивает `GET /about`, `/preorder`, `/how-to-order` или `/contacts`
- **THEN** ответ имеет статус 200 и HTML-документ
- **AND** документ содержит заголовок первого уровня, текст-заглушку и кнопку «Назад»

#### Scenario: Общая шапка и меню на заглушке
- **WHEN** клиент открывает любую страницу-заглушку
- **THEN** на ней доступны общая шапка сайта с основными пунктами и кнопка меню
- **AND** меню открывается и показывает полный список разделов

#### Scenario: Кнопка «Назад» ведёт на главную
- **WHEN** пользователь активирует кнопку «Назад» на странице-заглушке
- **THEN** открывается главная страница `/`

#### Scenario: Собственные метаданные заглушек
- **WHEN** сравниваются страницы `/about` и `/contacts`
- **THEN** их `title` и `description` различаются

### Requirement: Неизвестный адрес возвращает 404
Система SHALL возвращать статус 404 для адресов, которых нет среди страниц сайта, и MUST NOT отдавать для них страницу с кодом 200.

#### Scenario: Запрос несуществующей страницы
- **WHEN** клиент запрашивает `GET /no-such-page`
- **THEN** ответ имеет статус 404
- **AND** тело ответа содержит HTML-страницу ошибки

### Requirement: Публичные страницы не требуют авторизации
Система SHALL отдавать страницы каркаса любому клиенту без токена, cookie или иных учётных данных.

#### Scenario: Анонимный запрос страницы
- **WHEN** клиент без токена и cookie запрашивает любую страницу каркаса
- **THEN** ответ имеет статус 200 и не требует авторизации

### Requirement: Страница содержит базовые метаданные
Каждая страница каркаса SHALL содержать непустые `title` и `description`, абсолютный `canonical` и ровно один заголовок первого уровня.

#### Scenario: Метаданные главной страницы
- **WHEN** клиент запрашивает `GET /`
- **THEN** в HTML есть непустые `title`, `description`, `canonical` и один `h1`

#### Scenario: Метаданные различаются между страницами
- **WHEN** клиент запрашивает главную страницу и любую страницу-заглушку
- **THEN** значения `title` и `description` у этих страниц различаются

### Requirement: Навигация использует обычные ссылки
Система SHALL использовать для переходов между страницами ссылки `<a href>` и серверную навигацию; прямой запрос адреса MUST возвращать ту же страницу, что и переход по ссылке.

#### Scenario: Прямой запрос адреса из ссылки
- **WHEN** клиент извлекает адрес ссылки со страницы и запрашивает его напрямую
- **THEN** возвращается соответствующая страница со статусом 200
